# How the code works

This guide explains what the two scripts in this repository do and why they are built the way they are. It assumes no background in reaction-diffusion, coral biology or 3D printing.

## What the project is for

Coral reefs are dying from rising sea temperatures. One way to help them recover is to place artificial structures on the sea floor that young corals (larvae) can settle on and grow. Corals attach more readily to rough, complex surfaces with sheltered nooks than to flat ones, so the shape of these structures matters.

This project generates such structures with code. The shape is a porous lattice of winding walls and channels, inspired by brain corals of the genus *Platygyra*, whose skeletons are covered in long meandering valleys. The intended material is calcium carbonate, the same mineral coral skeletons are made of, printed with a binder-jet 3D printer. Prototypes can also be printed in PLA plastic on an ordinary desktop printer.

## Why a script instead of modelling by hand

A structure like this could be sculpted by hand in a 3D program such as Blender. We chose to generate it with a Python script instead, because the aim is a method that anyone can repeat and test, not a single object.

| Modelled by hand | Generated by this script |
| ---------------- | ------------------------ |
| Each model depends on the designer's choices, which are hard to describe or repeat exactly | Every design comes from a short list of numbers. The same numbers always give the same model |
| Making a variant means redoing the work | A new variant takes one changed number and a few minutes of computer time |
| Wall thickness and channel width are judged by eye | Every model is measured automatically and the results are saved next to it |
| Printability problems are found after a failed print | Thin walls, narrow channels, overhangs, loose pieces and sealed pockets are fixed before export |
| Design choices are hard to compare fairly | Variants differ only in the settings you change, so their effect can be tested |
| Progress lives in a folder of files | Progress lives in the version history of this repository, with a written record for every model |

In short, a hand-made model is a result. This script is a method: other people can run it, check it, change one variable at a time and compare their results with ours.

## The idea in one paragraph

Imagine a box of jelly made of two flavours that react with each other and slowly spread out. Left alone, they sort themselves into winding stripes, much like the valleys on a brain coral. The script simulates this on a computer, freezes the pattern, turns one flavour into solid material and the other into open channels, cuts the result into a cylinder, removes anything a printer cannot make, and saves a 3D-printable file.

The chemistry being simulated is the **Gray-Scott reaction-diffusion model**, a well-studied mathematical model that produces natural-looking patterns from two simple rules: the chemicals react, and they spread. We use it because it gives meandering channels from a handful of numbers, not because corals actually grow this way.

## `coral_reef.py`: the coral structure

### Settings

All settings are in one block at the top of the file, so you can change the design without reading the rest of the code. The main groups are:

| Group | What it controls |
| ----- | ---------------- |
| Size | Diameter and total height in millimetres. The height includes the solid base |
| Simulation | Size of the virtual box (`GRID`), how long the simulation runs (`STEPS`), and the random starting arrangement (`SEED`) |
| Gray-Scott recipe | `F` and `K`: how fast one chemical is added and the other removed. `DU` and `DV`: how fast each one spreads. These decide the type of pattern |
| Pattern scale | `VOXELS_ACROSS`: how much of the pattern fits across the part. Fewer means bigger channels |
| Porosity | `SOLID_FRACTION`: how much of the cylinder is solid |
| Surface skin | How much the outside is closed up, so it looks like a coral surface rather than a sliced sponge |
| Printability | Thinnest wall, narrowest channel and steepest overhang allowed |
| Mesh | How smooth and how large the final file is |
| Screw hole | Size of the threaded M3 hole in the bottom, used to mount the model on the base plate |

### Step 1: simulate the pattern (`simulate` and `laplacian`)

The script fills a 3D grid of tiny cubes (voxels) with two virtual chemicals, U and V.

1. Every cube starts full of U and empty of V.
2. Small random patches of V are added, like drops of food colouring in water. `SEED` decides where they land, so the same seed always gives the same starting point.
3. The script then repeats the same update thousands of times. In every cube, V consumes U and multiplies, U is topped up, V slowly disappears, and both chemicals spread to neighbouring cubes, U faster than V.

`laplacian` handles the spreading. It compares each cube with its six neighbours and moves chemical from high to low. The edges of the box wrap around, so the pattern has no seams.

After enough steps, V settles into a stable 3D labyrinth of connected walls.

### Step 2: turn the pattern into a solid (`build_solid`)

This step turns the chemical pattern into a printable object.

1. **Scale.** Stretch the pattern to the real size of the part and refine it for a smoother surface.
2. **Cut to a cylinder.** Mark which cubes are inside the cylinder.
3. **Choose solid and air.** Pick a concentration cut-off so that exactly `SOLID_FRACTION` of the cylinder becomes solid. Everything above it is solid; everything below is an open channel.
4. **Surface skin.** Near the outside, nudge the pattern towards solid so channel openings narrow into grooves.
5. **Add a base and screw boss.** Add a solid floor and a solid post in the centre, so the screw thread has material to cut into.
6. **Enforce minimum sizes.** Fill channels too narrow to clean out and remove walls too thin to print. This works by rolling an imaginary ball of the minimum size through the part (`open_mm`): anything the ball cannot fit into is changed.
7. **Remove overhangs (optional).** Rebuild the part layer by layer from the bottom and remove any solid with nothing close enough underneath to hold it up. This lets PLA prototypes print without support material. Binder-jet printing does not need it, because loose powder holds up every layer; set `MAX_OVERHANG_DEG = None` to turn it off.
8. **Remove loose pieces.** Keep only the largest connected piece, so nothing falls off.
9. **Fill sealed pockets.** Fill any air pocket with no way out. In binder-jet printing these would trap unbound powder inside the part.

### Step 3: measure it (`local_thickness` and `feature_sizes`)

For every point in a wall, the script finds the largest ball that fits inside the wall there; its diameter is the wall thickness at that point. It does the same in the channels to get channel width. This method is commonly used to measure porous materials such as bone and tissue scaffolds. The results are summarised in the JSON record.

### Step 4: make a printable mesh (`to_mesh`)

The model is still a block of tiny cubes. The marching cubes algorithm wraps a smooth surface of triangles around them, and the mesh is then simplified to keep the file small, but only if it stays watertight (a closed surface with no holes, which printers need).

### Step 5: cut the screw thread (`add_screw_hole`)

The script cuts a threaded M3 hole up into the centre of the bottom face. The thread is made by taking a small circle placed slightly off-centre and pushing it upward while twisting it one full turn per thread pitch (0.5 mm). The off-centre circle sweeps out a spiral groove. This groove is subtracted from the model with an exact geometric operation (the `manifold3d` library), the digital equivalent of drilling and tapping a hole.

The thread profile is rounded rather than the standard sharp 60-degree metric shape. It is designed to mate with the printed studs on the base plate; check the fit before using commercial M3 screws.

### Step 6: save the results (`preview`, `software_versions` and `main`)

`main` runs every step in order and writes three files:

| File | Contents |
| ---- | -------- |
| `coral_cylinder_seed<N>.stl` | The printable model, in millimetres |
| `coral_cylinder_seed<N>_params.json` | Every setting used, the measurements, and the Python and library versions |
| `coral_cylinder_seed<N>_preview.png` | Two horizontal slices (black = solid, white = channel) and a 3D view |

## `base_plate_studs.py`: the mounting plate

This script makes a flat plate with threaded studs. Each coral model screws onto one stud, so several models can be placed, moved and retrieved together.

1. **Layout (`axis_positions`, `layout`).** Spread the studs evenly so each model has room at the plate edge (`EDGE_MARGIN_MM`) and between neighbours. The script warns if models would be too close. `MODEL_FOOTPRINT_MM` must match the coral's diameter.
2. **Studs (`build_mesh`).** Make one threaded stud with the same twisted off-centre circle as the coral's hole, made 0.1 mm smaller all round (`FIT_CLEARANCE_MM`) so printed parts screw together. Bevel the tip so it finds the hole easily.
3. **Fuse.** Join a stud to the plate at every position, sunk slightly into the plate, so the result prints as one piece.
4. **Save.** Write the STL, an optional 3MF, a JSON record and a preview of the layout.

The thread settings in both scripts must match, or the models will not screw on.

## How this makes the work reproducible

| Feature | What it guarantees |
| ------- | ------------------ |
| Fixed random `SEED` | The same settings always produce the same model |
| One settings block per script | Every design decision is visible and changeable in one place |
| A JSON record saved with every model | Each model carries its exact recipe, its measurements and the software versions that made it |
| Measurements in millimetres | Results can be compared with printer limits and with coral biology |
| Automatic checks before export | Every exported model is a single, watertight, printable piece |
| Free, open-source libraries with pinned versions | Anyone can run the scripts without paid software |
| Version history in this repository | Every change to the method is recorded and can be traced back to the models it produced |

To rebuild any published model, see "Reproducing a result" in the [README](/README.md)
